# สรุปงาน fishpump: เฟิร์มแวร์ 0.4.0 และ ThingsBoard

อัปเดต: 2026-11-21

ระบบควบคุมปั๊มน้ำและการทำความเย็นสำหรับบ่อปลา บนบอร์ด ESP32-S3 ใช้งานได้ 2 ทาง:
- **เว็บแอปในบอร์ด:** ใช้ได้แม้ไม่มีอินเทอร์เน็ต
- **ThingsBoard ผ่าน MQTT:** ดูข้อมูลย้อนหลังและสั่งงานจากระยะไกล เป็นฐานของแอป frontend ที่จะทำต่อ

กฎแจ้งเตือนและระบบป้องกันทั้งหมดทำงานในเฟิร์มแวร์ ThingsBoard เก็บข้อมูล แสดงผล และส่งคำสั่ง

### ThingsBoard MQTT (milestone 1–6)

1. **ลิงก์:** MQTT ลงทะเบียนอุปกรณ์เอง ต่อใหม่เองแบบ backoff มีการ์ดในเว็บแอป SNTP และ rule chain ที่แปลงเหตุการณ์เป็น alarm
2. **`device_api` + RPC:** ตาราง method เดียวที่เว็บและ ThingsBoard ใช้ร่วมกัน ครบทุกฟังก์ชันของเว็บแอป มี dashboard ทดสอบ และสคริปต์ parity พิสูจน์ว่าสองทางตอบตรงกัน
3. **สถานะ:** ค่าตั้งเป็น client attribute ส่วนสถานะเป็น telemetry แก้จากเว็บแล้ว ThingsBoard เห็นภายใน 2 วินาที
4. **เปลี่ยน Wi-Fi จากระยะไกล:** ใช้ staging ยืนยันเองเมื่อต่อ ThingsBoard ติด ไม่งั้นย้อนกลับ
5. **อัปเดตเฟิร์มแวร์จาก ThingsBoard:** ตรวจ SHA-256 และย้อนกลับเองถ้าอิมเมจใหม่ต่อ ThingsBoard ไม่ได้ใน 5 นาที
6. **ทดสอบความทนทาน:**
   - TLS ผิดพอร์ตล้มอย่างสะอาด
   - host ผิดแล้วกลับมาต่อได้
   - ThingsBoard ล่ม 38 นาทีแล้วส่งเหตุการณ์ย้อนหลังตามลำดับ
   - ทดสอบต่อเนื่อง 1 ชั่วโมง: RPC 70/70 คำสั่งตอบทั้งหมด, heap ต่ำสุด 107.5 KB
   - หลัง milestone 6 แก้ข้อความ error ของ TLS บนการ์ดให้บอกชัดว่าเป็นเรื่อง TLS

ฝั่งเซิร์ฟเวอร์ (`thingsboard/`):
- `tb_setup.py` ตั้งค่าซ้ำได้ ไม่ต้องตั้งเอง: rule chain, device profile พร้อมการลงทะเบียนเอง, customer ทดสอบ และ dashboard ทดสอบ
- `tb_ota.py` อัปโหลดเฟิร์มแวร์
- `parity_test.py` และ `api_golden.py` ตรวจว่าเว็บ API กับ RPC ตอบตรงกัน

## สิ่งที่ทดสอบบนบอร์ดจริงแล้ว

- **เว็บแอปและแจ้งเตือน:** กระดิ่ง overlay เสียง LED ทุกระดับ การรับทราบ กฎแบบ gate และ latch ความปลอดภัยของ API (401/403/400) และ log 3 ชั่วโมงที่มี 3 แท็บเปิดพร้อมกัน
- **ป้องกันเดินแห้ง (ใช้จัมเปอร์แทน flow switch):** ตัดที่เวลาที่ตั้ง backoff 60/120/240 วินาที และล็อกหลังครบจำนวนครั้ง
- **ThingsBoard:**
  - การเชื่อมต่อ การลงทะเบียน และ telemetry
  - RPC ทุกกลุ่ม (parity ผ่าน)
  - attribute และสถานะ
  - เปลี่ยน Wi-Fi แบบย้อนกลับ
  - OTA สำเร็จ, OTA ย้อนกลับ และอิมเมจเสีย
  - ThingsBoard ล่มแล้วต่อกลับ และทดสอบต่อเนื่อง 1 ชั่วโมง
- **ยังไม่ได้ทดสอบ:** เซนเซอร์จริง (PZEM, pH, PT100 ขึ้น fault บนบอร์ดทดสอบเพราะยังไม่ได้ต่อ) ปั๊มจริง และข้ออื่นใน [`bench-test-pending.md`](bench-test-pending.md)

## การตัดสินใจหลักที่ควรรู้

- **ThingsBoard ทำได้เท่าเว็บแอป** (full parity) ยกเว้นเปลี่ยนขา GPIO และรหัสผ่านเว็บ ซึ่งทำได้เฉพาะในเครื่อง
- **คำสั่งเขียนทุกอย่างเป็น RPC ไม่ใช่ shared attribute** เพื่อให้การแก้ล่าสุดชนะเสมอไม่ว่ามาจากทางไหน และ ThingsBoard ไม่แสดงค่าเก่า
- **เปลี่ยน Wi-Fi และอัปเดตเฟิร์มแวร์จากระยะไกลต้องย้อนกลับเองได้** บอร์ดต้องไม่หลุดจนต้องมีคนไปที่หน้างาน
- **ThingsBoard ล่มหรือไม่มีเน็ต ต้องไม่ทำให้ฟังก์ชันในเครื่องหายแม้แต่อย่างเดียว**
