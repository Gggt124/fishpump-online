## 5. กระดิ่งแจ้งเตือน

**หมายเหตุสำคัญเรื่องตัวเลข:** ตัวเลขบนกระดิ่งนับ **เหตุการณ์ที่ยังไม่เห็น + แจ้งเตือนที่ยัง active อยู่** ดังนั้นถ้ามีแจ้งเตือนที่ยังไม่หายขณะคุณเปิดกระดิ่ง ตัวเลขจะ **ไม่ลดเหลือ 0** (ตัวเลขนี้เท่ากับป้ายที่เมนูแจ้งเตือน) นี่ **ไม่ใช่ความผิดพลาด** ให้ดูผลหลังแจ้งเตือนหายแล้วเท่านั้น

สร้างกฎทดสอบก่อน: ค่าที่ตรวจ **เวลาทำงาน (uptime_sec)** **มากกว่า** (uptime ตอนนี้ + 60) ดีเลย์ 5 วินาที ระดับ **เตือน** ไม่ latch (ดูวิธีดู uptime ที่หน้าสถานะระบบ)

1. **ทำ:** เปิดหน้า **แผงควบคุม** (ไม่ใช่หน้าแจ้งเตือน) แล้วรอให้กฎเกิด
   **ต้องเห็น:** ภายใน **ประมาณ 3 วินาที** หลังกฎเกิด ตัวเลขขึ้นที่กระดิ่ง (รอบก่อนรอได้ถึง 10 วินาที)
   - [ ] ผ่าน  บันทึก: ______________________
2. **ต้องเห็น (พร้อมข้อ 1):** ชื่อแท็บเบราว์เซอร์ขึ้นต้นด้วย **`(n) `** เมื่อ n > 0 (ดูที่แถบแท็บ) และกลับเป็นชื่อปกติเมื่อเป็น 0
   - [ ] ผ่าน  บันทึก: ______________________
3. **ทำ:** (เฉพาะมือถือ หรือย่อหน้าต่างเบราว์เซอร์ให้แคบ) ดูเมนูล่าง
   **ต้องเห็น:** ปุ่ม **"เพิ่มเติม"** มี **จุดแดง** เมื่อมีแจ้งเตือน และไม่มีเมื่อเป็น 0 กระดิ่งไม่บังปุ่มสลับธีมที่หัวหน้า
   - [ ] ผ่าน  บันทึก: ______________________
4. **ทำ:** กดกระดิ่ง
   **ต้องเห็น:** แผงแสดงเหตุการณ์ล่าสุดไม่เกิน 5 รายการ ใหม่สุดอยู่บน ปุ่ม **"ดูทั้งหมด"** พาไปหน้าแจ้งเตือน ตัวเลขที่ค้างเป็นเพราะแจ้งเตือนยัง active (ดูหมายเหตุด้านบน) กดนอกแผงหรือกด Esc แผงปิด
   - [ ] ผ่าน  บันทึก: ______________________

   **ต้องเห็น:** ตัวเลข **ไม่หายเอง** (ยังนับเหตุการณ์ "หาย" ที่ยังไม่ได้ดู) จนกว่าจะกดเปิดกระดิ่ง พอเปิดแล้วตัวเลขเป็น **0** และแท็บกลับเป็นชื่อปกติ

## 6. Overlay เหตุวิกฤต + เสียง

สร้างกฎ: ค่าที่ตรวจ **เวลาทำงาน (uptime_sec)** **มากกว่า** (uptime ตอนนี้ + 30) ดีเลย์ 5 วินาที ระดับ **วิกฤต** ไม่ latch

**เสียง:** เบราว์เซอร์ไม่ให้เล่นเสียงจนกว่าคุณจะ **คลิกอะไรสักอย่างบนหน้านั้นหนึ่งครั้ง** หลังเปิดหน้า (กฎของเบราว์เซอร์ ไม่ใช่บั๊ก) ให้คลิกที่หน้าว่างๆ หนึ่งครั้งก่อนรอ

1. **ทำ:** คลิกหน้าหนึ่งครั้ง แล้วรอให้กฎเกิด
   **ต้องเห็น:** overlay เต็มจอขึ้น มีปุ่ม **"รับทราบทั้งหมด"** และ **"ปิดไว้ก่อน"** และ **ได้ยินเสียงบี๊ป 3 ครั้ง** ซ้ำทุก ~5 วินาที

## 7. สี LED ตามระดับ

ดูที่ LED บนบอร์ด ใช้กฎทดสอบ `uptime_sec` ทำให้เกิดแจ้งเตือนทีละระดับ (แก้ระดับของกฎเดียวได้ แล้วรอให้เกิดใหม่)

**ลำดับความสำคัญ:** สถานะอื่นของ LED (กดปุ่มค้าง, โหมด recovery AP, factory reset, staging) **ทับสีแจ้งเตือนเสมอ** จากนั้น วิกฤต > เตือน > ข้อมูล > สีเขียว "AP เปิด"

**ระวัง:** แจ้งเตือนระดับ **เตือน/ข้อมูล ที่ยังไม่รับทราบ จะบังสีเขียว "AP เปิด"** (ตั้งใจตามดีไซน์) ดังนั้นถ้า LED เป็นเหลืองหรือน้ำเงินแล้วไม่เห็นเขียว ไม่ใช่ความผิดพลาด

- [ ] ไม่มีแจ้งเตือนที่ยังไม่รับทราบ: LED เขียว (AP เปิด) ตามปกติ
- [ ] **วิกฤต** ที่ยังไม่รับทราบ: **แดงกระพริบ** (1 Hz)
- [ ] **เตือน** ที่ยังไม่รับทราบ: **เหลืองค้าง** (ไม่กระพริบ)
- [ ] **ข้อมูล** ที่ยังไม่รับทราบ: **น้ำเงินค้าง** (ไม่กระพริบ ต่างจาก recovery AP ที่น้ำเงิน **กระพริบ**)
- [ ] มีหลายระดับพร้อมกัน: แสดงระดับสูงสุด (วิกฤต ก่อน เตือน ก่อน ข้อมูล)
- [ ] กด **รับทราบ** แล้ว: LED กลับเป็นเขียวปกติ (แม้แจ้งเตือนยัง active อยู่ ถ้ารับทราบครบทุกข้อ)

## คำสั่ง API (ใช้ได้ใน Windows PowerShell 7 ตามนี้)

ระบบยืนยันตัวตนด้วย **คุกกี้ `session`** ที่ได้จาก `POST /api/login` และทุก POST ต้องมีหัว `Origin: http://192.168.4.1` (ตรงกับที่อยู่บอร์ด) ใน PowerShell ห้ามใช้ `curl` เฉยๆ (มันคือ alias ของ Invoke-WebRequest) ให้ใช้คำสั่งด้านล่าง ซึ่งเก็บคุกกี้ไว้ใน `$s` ให้เอง ทำจากเครื่องที่ต่อ Wi-Fi ของบอร์ดอยู่

**login (ทำครั้งเดียวต่อหน้าต่าง PowerShell)**

```powershell
$pw = Read-Host 'รหัสผ่าน admin'
$h = @{ Origin = 'http://192.168.4.1' }
$body = @{ username = 'admin'; password = $pw } | ConvertTo-Json -Compress
Invoke-RestMethod -Uri http://192.168.4.1/api/login -Method Post -ContentType 'application/json' -Headers $h -Body $body -SessionVariable s
```

ต้องได้ `ok : True` (ถ้าได้ `require_password_change` ให้เปลี่ยนรหัสผ่านที่หน้าเว็บก่อน)

**ตัวช่วยสำหรับข้อ F, G, H** (วางครั้งเดียวหลัง login ฟังก์ชันนี้ส่ง POST แล้วพิมพ์ endpoint กับรหัสสถานะ)

```powershell
$eps = @(
  @{ uri = '/api/alarms/rules';         ok = '{"name":"x"}' },
  @{ uri = '/api/alarms/rules/delete';  ok = '{"id":1}' },
  @{ uri = '/api/alarms/ack';           ok = '{"all":true}' },
  @{ uri = '/api/protection';           ok = '{"pump":{}}' },
  @{ uri = '/api/protection/measure';   ok = '{"action":"stop"}' }
)
function Test-Post($uri, $json, $origin, $useSession) {
  $hh = @{ Origin = $origin }
  $p = @{ Uri = "http://192.168.4.1$uri"; Method = 'Post'; ContentType = 'application/json'; Headers = $hh; Body = $json; SkipHttpErrorCheck = $true }
  if ($useSession) { $p.WebSession = $s }
  $r = Invoke-WebRequest @p
  '{0,-28} {1}  {2}' -f $uri, [int]$r.StatusCode, $r.Content
}
```

**F. ไม่มี session → ต้องได้ `401` ทุกบรรทัด** (ไม่ใส่ `-WebSession` Origin ถูก เพื่อไม่ให้ไปชนผลข้อ 403)

```powershell
foreach ($e in $eps) { Test-Post $e.uri $e.ok 'http://192.168.4.1' $false }
```

ทุกบรรทัดต้องได้ `401` และ `{"ok":false,"error":"unauthorized"}`

**F2. GET ไม่ login → 401**

```powershell
foreach ($u in '/api/alarms/status','/api/alarms/summary','/api/protection','/api/uplink/preview') {
  $r = Invoke-WebRequest -Uri "http://192.168.4.1$u" -SkipHttpErrorCheck
  '{0,-24} {1}' -f $u, [int]$r.StatusCode
}
```

**G. มี session แต่ Origin ผิด → ต้องได้ `403`** (`forbidden`)

```powershell
foreach ($e in $eps) { Test-Post $e.uri $e.ok 'http://evil.example' $true }
```

ทุกบรรทัดต้องได้ `403` (ไม่มีอะไรถูกลบ/รับทราบ/ตั้งค่า เพราะถูกปฏิเสธก่อนอ่าน body)

**H. มี session + Origin ถูก + JSON ผิด → ต้องได้ `400`**

```powershell
foreach ($e in $eps) { Test-Post $e.uri 'not json' 'http://192.168.4.1' $true }
```

ทุกบรรทัดต้องได้ `400` และ `"error":"invalid_json"` (ไม่มีอะไรเปลี่ยนในบอร์ด)

**H2. JSON ถูกแต่ข้อมูลผิด → `400` พร้อมชื่อช่อง** (ไม่บังคับ)

```powershell
Test-Post '/api/alarms/rules' '{"name":"x"}' 'http://192.168.4.1' $true
Test-Post '/api/protection' '{"pump":{"enabled":true,"prime_sec":0,"dry_trip_sec":10,"retry_wait_min":5,"retry_backoff":true,"max_retries":3}}' 'http://192.168.4.1' $true
```

ต้องได้ `400` ทั้งสองบรรทัด ข้อแรก `"message":"signal"` ข้อสอง `"message":"prime_sec"` (ข้อสองไม่เปลี่ยนค่าในบอร์ดเพราะถูกปฏิเสธ)

**E. ดู uplink preview**

```powershell
$u = Invoke-RestMethod -Uri http://192.168.4.1/api/uplink/preview -WebSession $s
$u | Select-Object connected, pending_events, waiting_for_clock, dropped | Format-List
```

ต้องเห็น `waiting_for_clock : False` (ไม่มีตัวส่ง) และ `pending_events` เป็นตัวเลข

**ดูสรุปแจ้งเตือน (ใช้ตรวจข้อ 5)**

```powershell
Invoke-RestMethod -Uri http://192.168.4.1/api/alarms/summary -WebSession $s | ConvertTo-Json -Depth 5
```

ต้องเห็น `critical_unacked`, `warning_unacked`, `info_unacked`, `last_critical_seq`
