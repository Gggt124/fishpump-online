# คู่มือทดสอบบนบอร์ด: release, คีย์ OTA และชุดติดตั้ง

ผู้ทดสอบ: เจ้าของโปรเจกต์ (แฟลชและต่อ Wi-Fi เองทั้งหมด) ต้องมี release จาก CI หรือ build ในเครื่อง ดู [`docs/release/`](release/README.md)

> สถานะ: `[ ]` ยังไม่ทำ · `[/]` ผ่าน · `[x]` ไม่ผ่าน (จดอาการในบรรทัด "บันทึก")
> ต่อ Wi-Fi `FishPump-Setup` แล้ว PC จะไม่มีอินเทอร์เน็ต เปิดไฟล์นี้ไว้ก่อน
> log ดูที่ USB (COM12): `idf.py -C firmware -p COM12 monitor`

**รอบที่ 1 (2026-11-22):** ใช้ไฟล์จาก prerelease `v0.4.0-rc1` (commit `b660fa9`, ลายนิ้วมือคีย์ `1fadb59d`) บอร์ด ESP32-S3 บนโต๊ะ ไม่ต่อโหลดจริง ต่อสายที่ COM12 (พอร์ต USB ในตัวชิป ยังไม่ได้ลองช่อง UART) Claude รันทุกข้อ เจ้าของพิมพ์รหัสผ่าน ThingsBoard และรหัส admin ของบอร์ดเองในแท็บ Terminal

---

### R1. ลายนิ้วมือคีย์: ไฟล์กับ log บูต

1. สร้าง release (หรือ build ในเครื่องด้วยคีย์ทดสอบ) แล้วดูลายนิ้วมือในชื่อไฟล์ `fishpump-<ver>-<fp>.ota.bin`
2. แฟลชบอร์ดด้วยไฟล์นั้น แล้วดู log บูต
   **ต้องเห็น:** บรรทัด `OTA key fp=<fp> (release)` และ `<fp>` เท่ากับในชื่อไฟล์
   - [/] ผ่าน  บันทึก: log บูต `OTA key fp=1fadb59d (release)` ตรงกับชื่อไฟล์ ทั้งหลัง ThingsBoard OTA, web OTA และหลังแฟลช factory.bin ทุกครั้ง `status.get` ได้ `ota_key_fp=1fadb59d`, `ota_key_dev=false`

### R2. ย้ายบอร์ดจากคีย์ศูนย์เป็นคีย์จริง (ไม่ต้องต่อสาย)

ทำตาม "ย้ายบอร์ดจากคีย์ศูนย์" ใน [`release/keys.md`](release/keys.md) กับบอร์ดที่ยังรันคีย์ศูนย์
**ต้องเห็น:** หลังรีบูต `status.get` มี `ota_key_dev` เป็น false และ `ota_key_fp` เท่ากับลายนิ้วมือของ release (ThingsBoard ก็เห็น `tb_link.ota_key_fp` ตรงกัน)
- [/] ผ่าน  บันทึก: บอร์ดเดิมรัน 0.3.2 (คีย์ศูนย์) ใช้ทางเว็บไม่ได้เพราะ firmware เก่ามีเพดาน 413 จึงย้ายผ่าน ThingsBoard OTA: package `fishpump` 0.4.0 (ไฟล์ธรรมดาของ rc) ดาวน์โหลด 126 chunk ผ่าน VERIFIED แล้วรีบูตเข้าคีย์จริง ยังไม่ได้ดู attribute `tb_link.ota_key_fp` บน ThingsBoard

### R3. web OTA ไม่ติด 413

อัปโหลดไฟล์ `.ota.bin` ของรุ่น 0.4.x (ใหญ่ประมาณ 2.07 MB) ทางหน้าเว็บ
**ต้องเห็น:** ไม่ได้ `file_too_large` อัปโหลดสำเร็จและบอร์ดรีบูตด้วยเวอร์ชันใหม่
- [/] ผ่าน  บันทึก: `fishpump-0.4.0-rc1-1fadb59d.ota.bin` 2,062,016 ไบต์ ผ่าน `POST /api/ota` (สคริปต์เดียวกับที่หน้าเว็บส่ง raw body) ได้ HTTP 200 ใน 21.3 วินาที แล้วรีบูตกลับมาที่ fp เดิม ไม่ได้กดผ่านหน้าเว็บจริง

### R4. ไฟล์ที่เข้ารหัสด้วยคีย์ผิด

เข้ารหัสไฟล์ธรรมดาด้วยคีย์อื่นที่ไม่ใช่ของบอร์ด แล้วอัปโหลดทางเว็บ
**ต้องเห็น:** บอร์ดไม่รับหรือไม่บูตเข้า image ใหม่ และกลับมารันเวอร์ชันเดิมได้ (จด log และข้อความที่หน้าเว็บแสดง)
- [/] ผ่าน  บันทึก: ไฟล์ rc เข้ารหัสด้วยคีย์ศูนย์ (fp `66687aad`) ได้ HTTP 500 `ota_write_failed` ใน 0.1 วินาที บอร์ดไม่รีบูตและ `status.get` ยังตอบปกติ หน้าเว็บจะแสดง "เกิดข้อผิดพลาดในการอัปเดต (HTTP 500)"

### R5. FLASH.bat กับบอร์ดเปล่า

แตก `flash-package.zip` ใน Windows แล้วดับเบิลคลิก `FLASH.bat` กับบอร์ดที่ล้างแล้ว (เสียบช่อง COM/UART)
**ต้องเห็น:** `[OK] Firmware installed.` บอร์ดบูต และ Wi-Fi `FishPump-Setup` ขึ้น
- [/] ผ่าน  บันทึก: รัน `tools\flash_and_show.ps1 -Port COM12` จาก zip ของ rc (ตัวเดียวกับที่ FLASH.bat เรียก) ได้ `[OK] Firmware installed.` hash ตรวจผ่าน แสดงรหัส AP 8 ตัว บอร์ดบูตเป็นโหมด AP (`mode=3 ap=true sta_configured=false`) ใช้พอร์ต USB ในตัวชิป ไม่ได้ลองช่อง UART และไม่ได้ดับเบิลคลิกจริง ข้อที่พบ: esptool v5 เตือน `write_flash` deprecated แก้แล้วใน branch `fix/release-bench-findings`

### R6. SHOW_PASSWORD.bat

รัน `SHOW_PASSWORD.bat` กับบอร์ดจาก R5
**ต้องเห็น:** รหัสที่แสดงใช้ต่อ Wi-Fi `FishPump-Setup` ของบอร์ดนั้นได้จริง (และตรงกับที่ `FLASH.bat` แสดงตอนติดตั้ง)
- [/] ผ่านครึ่งหนึ่ง  บันทึก: รหัสจาก `show_ap_password.ps1` ตรงกับที่ flash แสดง (เทียบโดยไม่พิมพ์รหัส) รูปแบบฐานสิบหกตัวใหญ่ 8 ตัว **ยังไม่ได้ลองต่อ Wi-Fi จริง** (ต่อ AP แล้ว PC ไม่มีเน็ต) เจ้าของยืนยันตอนตั้งค่าบอร์ดใหม่

### R7. ThingsBoard OTA หลังย้ายคีย์

อัปโหลด `fishpump-<ver>.bin` (ธรรมดา) เป็น package ใน ThingsBoard ตามปกติ
**ต้องเห็น:** อัปเดตสำเร็จเหมือนเดิม (`UPDATED`) และ attribute `tb_link.ota_key_fp` ยังตรงกับ release
- [ ] ยังไม่ทำ  บันทึก: ต้องมีเวอร์ชันที่ต่างจาก 0.4.0 ที่บอร์ดรัน (ThingsBoard OTA ไม่ส่งเวอร์ชันเดิม) ทำตอน release 0.4.1 และบอร์ดต้องผูก ThingsBoard ใหม่ก่อน (token ถูกลบใน R5/R8) R2 แสดงแล้วว่า ThingsBoard OTA ใช้ไฟล์ธรรมดาได้

### R8. ERASE_FLASH.bat แล้วติดตั้งซ้ำ

รัน `ERASE_FLASH.bat` (พิมพ์ YES) แล้ว `FLASH.bat` อีกครั้ง
**ต้องเห็น:** บอร์ดว่างหลัง erase (ไม่บูตเข้าแอป) และกลับมาใช้งานได้หลังติดตั้งซ้ำ
- [/] ผ่าน  บันทึก: ตอบอย่างอื่นที่ไม่ใช่ YES ได้ "Cancelled." พิมพ์ YES แล้วลบสำเร็จ log บูตวน `invalid header: 0xffffffff` ไม่มีแอป ติดตั้งซ้ำแล้วบูต fp `1fadb59d` หลังแก้ชื่อคำสั่ง esptool (`erase-flash`, `write-flash`, `read-mac`) รันลบ ติดตั้ง และอ่านรหัสซ้ำอีกรอบ ไม่มีคำเตือนและรหัสตรงเดิม
