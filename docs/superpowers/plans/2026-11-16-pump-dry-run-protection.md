# Pump Dry-Run Protection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop the water pump when it runs dry, retry with back-off, lock it after too many trips, and keep the alarm visible until flow returns or a person acknowledges. Installers configure it from the dashboard.

**Architecture:** The work is split into four parts:
- **Pure state machine.** A new component, `dry_run_logic`, holds all timing and decisions. It is tested in the QEMU self-test with synthetic time.
- **Glue.** A second new component, `dry_run_guard`, runs a 1 s task. It reads `pump_control` and `flow_switch` status, steps the state machine, and acts. It sets the guard state on `pump_control`, raises and clears a **system alarm** in `alarm_engine`, and persists settings and the lock flag in NVS.
- **Pump control changes.** `pump_control` gains a guard state, which inhibits relay 1 while the guard is in WAIT or LOCKED, and a relay-1 test mode for the "measure" button.
- **Engine changes.** `alarm_engine` gains system alarms: alarms owned by a module, outside the user rule set.

**Tech Stack:** ESP-IDF v6.0.1 (C, `-Werror`), FreeRTOS, cJSON, vanilla JS web UI, Python static contract checks, QEMU self-test.

**Spec:** `docs/superpowers/specs/2026-11-16-pump-dry-run-protection-design.md`. Read it fully before Task 1. Its section numbers (§) are cited below.

## Review Focus

These are the five cases most likely to hurt a real installation:

1. **Locked pump after a reboot.** A pump that was LOCKED before a power cut must still be off after boot: no relay-1 pulse during `pump_control_init` auto-start, and the alarm raised again. Pinned in Task 4 (init context) and Task 5 (glue raises on boot).
2. **Dashboard start while inhibited.** It must answer 409 and must **not** call `pump_control_stop_water()`, because `handle_api_pump_start` does that on failure and would erase the user's running intent. Pinned in Task 6.
3. **Short ON periods.** An ON period shorter than `prime_sec + dry_trip_sec` must still trip after enough cycles. Pinned in Task 2.
4. **Float-driven set switch while inhibited.** `apply_water_set_start_phase` energises relay 1 directly, so the inhibit must cover it. Pinned in Task 4.
5. **Acknowledge from the alarm list.** It must call back into the guard outside the engine lock, because the guard's handling calls `alarm_engine_system_clear`, which takes that lock. A deadlock here hangs the web server. Pinned in Task 3 by a static check, and covered by bench step 5 in Task 8.

```c
typedef enum { DRY_RUN_DISABLED = 0, DRY_RUN_MONITOR, DRY_RUN_WAIT, DRY_RUN_LOCKED } dry_run_state_t;

typedef struct {
    uint8_t state;          /* dry_run_state_t */
    uint8_t trips;
    bool alarm_active;
    bool relay_was_on;
    uint32_t on_since_ms;
    uint32_t dry_accum_ms;
    uint32_t flow_since_ms; /* 0 = no flow streak running */
    uint32_t wait_until_ms;
    uint32_t last_tick_ms;
} dry_run_rt_t;

typedef struct {
    bool relay_on;      /* pump_control water.relay_energized */
    bool flow_on;       /* flow_switch debounced */
    bool test_active;   /* measure button holds relay 1: invisible to the machine (§5.7) */
    bool water_running; /* user intent: water system started */
} dry_run_input_t;

/* Bit flags: what the glue must do after a call. */
#define DRY_RUN_ACT_INHIBIT        0x01 /* set pump guard WAIT/LOCKED (per new state) */
#define DRY_RUN_ACT_RELEASE        0x02 /* set pump guard MONITOR/OFF, no restart */
#define DRY_RUN_ACT_RELEASE_RESUME 0x04 /* set pump guard MONITOR, restart water schedule from ON */
#define DRY_RUN_ACT_RAISE          0x08 /* raise/re-raise the system alarm (§5.3: every trip re-alerts) */
#define DRY_RUN_ACT_CLEAR          0x10 /* clear the system alarm with out->clear_reason */
#define DRY_RUN_ACT_STATE_CHANGED  0x20 /* log one line; persist locked flag if entering/leaving LOCKED */

typedef struct {
    uint8_t actions;
    uint8_t clear_reason; /* ALARM_REASON_* value: 1 condition, 2 acked, 3 rule_changed */
    float value;          /* alarm value: trip number on RAISE, dry seconds otherwise */
} dry_run_out_t;

void dry_run_begin(dry_run_rt_t *rt, const dry_run_config_t *cfg, bool locked_at_boot, uint32_t now_ms);
void dry_run_step(const dry_run_config_t *cfg, dry_run_rt_t *rt, const dry_run_input_t *in,
                  uint32_t now_ms, dry_run_out_t *out);
void dry_run_ack(const dry_run_config_t *cfg, dry_run_rt_t *rt, bool water_running,
                 uint32_t now_ms, dry_run_out_t *out);
/* Call after saving new settings. enabled->disabled: DISABLED, RELEASE, CLEAR(rule_changed).
 * disabled->enabled: MONITOR with counters at 0. Otherwise keeps state. */
void dry_run_config_changed(const dry_run_config_t *old_cfg, const dry_run_config_t *new_cfg,
                            dry_run_rt_t *rt, uint32_t now_ms, dry_run_out_t *out);
uint32_t dry_run_wait_remaining_sec(const dry_run_rt_t *rt, uint32_t now_ms); /* 0 unless WAIT */
```

**Behaviour.** Follow spec §5.3–§5.6 exactly. Points the tests pin:
- `dry_run_begin` with `locked_at_boot` sets LOCKED, `alarm_active = true` and `trips = cfg->max_retries + 1`. The glue raises the alarm from that. A disabled config starts DISABLED, and `locked_at_boot` is ignored when disabled. Otherwise the state is MONITOR.
- **Accumulation** adds `now - last_tick` only while `relay_on && !test_active && now - on_since >= prime_sec*1000 && !flow_on`. A relay rising edge sets `on_since_ms`. `dry_accum_ms` is not touched on a relay falling edge.
- `flow_on && relay_on` sets `dry_accum_ms = 0`. When `alarm_active` and flow has held for `DRY_RUN_FLOW_CONFIRM_MS` while the relay is on: `trips = 0`, CLEAR(condition), `alarm_active = false`.
- **Trip** at `dry_accum_ms >= dry_trip_sec*1000`:
  - `trips++`
  - LOCKED if `trips > max_retries`, else WAIT with `wait_until = now + dry_run_wait_ms(cfg, trips)`
  - actions INHIBIT | RAISE | STATE_CHANGED, `value = trips`, `dry_accum_ms = 0`
- **WAIT expiry** (`(int32_t)(now - wait_until) >= 0`): MONITOR, then RELEASE_RESUME if `water_running`, else RELEASE, plus STATE_CHANGED. `trips` and `alarm_active` are kept. Set `relay_was_on = false`, so the restart is seen as a rising edge.
- **Ack** with `alarm_active`, in any state except DISABLED:
  - `trips = 0`, `dry_accum_ms = 0`, state MONITOR
  - RELEASE_RESUME if `water_running` and the state was WAIT or LOCKED; RELEASE if it was WAIT or LOCKED and the water was not running; no release if it was MONITOR
  - CLEAR(acked), `alarm_active = false`, STATE_CHANGED if the state changed
  - Ack without `alarm_active` does nothing.
- In DISABLED, `dry_run_step` does nothing.
