# สรุปผล bench test แจ้งเตือน (ไม่ต่อเซนเซอร์) — สิ่งที่ต้องแก้

วันที่: 2026-11-16 · ที่มา: บันทึกของผู้ใช้ใน [bench-test-alarms.md](../../bench-test-alarms.md) (ยังไม่ commit) · branch `feature/alarm-rules`

ข้อที่ไม่มีบันทึกถือว่าผ่าน รายการด้านล่างคือทุกข้อที่มีบันทึก เรียงตามความสำคัญ

## 1. [วิกฤต] กฎ "ปั๊มน้ำเปิดแต่น้ำไม่ไหล" ไม่ปกป้องปั๊มเมื่อปั๊มทำงานเป็นรอบ (ข้อ 1.4 และ 3.3)

**สิ่งที่ผู้ใช้พบ**
- ถ้าตั้งเวลาทำงานของปั๊มไว้ไม่เกิน 15 วินาที (ค่าหน่วงของกฎ) แจ้งเตือนจะไม่เกิดเลย
- ถ้าตั้งนานกว่าเล็กน้อย LED จะแดงแค่ช่วงสั้นๆ แล้วกลับเป็นเขียวตอนปั๊มพัก ซึ่งช่วงพักนานกว่าช่วงทำงาน ปั๊มจึงยังทำงานโดยไม่มีน้ำไหลวนไปเรื่อยๆ จนอาจพังได้
- ประวัติในบอร์ดมีรายการ "เกิด" กับ "หาย" สลับกันทุก 1-2 นาที ตั้งแต่ 19:59 ถึง 20:14 ประมาณ 10 คู่

**สาเหตุ (ตรวจกับโค้ดแล้ว)**
- กฎนี้ทำงานเฉพาะตอน `relay1_on` เป็นจริง ตาม spec เมื่อเงื่อนไขนี้ปิด (ปั๊มหยุด) แจ้งเตือนจะถูก**ล้างเป็น "หาย"** และตัวนับเวลาหน่วงจะเริ่มใหม่ทุกรอบที่ปั๊มเปิด
- เกือบทุกแถว "หาย" ในประวัติมีค่า **"ปิด"** หมายถึงน้ำยังไม่ไหล รายการหายไปเพราะปั๊มหยุด ไม่ใช่เพราะปัญหาหาย ประวัติจึงทำให้เข้าใจผิด แถวที่มีค่า "เปิด" มีแค่แถวเดียว (20:09) ซึ่งหายเพราะน้ำไหลจริง
- preset นี้ตั้ง `latch = false` ไว้ จึงไม่ค้างรอรับทราบ
- กฎทั้งระบบทำได้แค่**แจ้งเตือน** ไม่มีกฎไหนสั่งหยุดปั๊ม
- รายการ "เกิด/หาย" ที่ซ้ำทุกรอบยังเบียดเหตุการณ์อื่นออกจากที่เก็บในบอร์ด ซึ่งจุได้ 32 รายการ

**แนวทางแก้ (ต้องตัดสินใจก่อนเขียนแผน)**
- ก. ให้แจ้งเตือนแบบนี้**คงสถานะไว้เมื่อปั๊มหยุด** แทนการล้าง ตอนปั๊มหยุดไม่มีทางรู้ว่าน้ำไหลหรือไม่ จึงควรถือว่า "ยังไม่รู้" ไม่ใช่ "หายแล้ว" ให้หายเฉพาะตอนเห็นน้ำไหลจริงขณะปั๊มเปิด
- ข. **นับเวลาที่น้ำไม่ไหลสะสมข้ามรอบ** แทนการเริ่มนับใหม่ทุกรอบ เพื่อแก้กรณีที่ช่วงทำงานสั้นกว่าค่าหน่วง หรือให้ UI เตือนเมื่อช่วงทำงานของปั๊มไม่เกินค่าหน่วงของกฎ
- ค. ตั้ง preset นี้เป็น latch คือค้างจนกดรับทราบ
- ง. **ระบบป้องกัน dry-run:** เมื่อกฎนี้เกิด ให้หยุดปั๊มและล็อกตารางอัตโนมัติไว้จนกดรับทราบ ข้อนี้เป็นการสั่งงานอุปกรณ์จริง ผู้ใช้ต้องเป็นคนตัดสิน (เช่น ปิดได้ไหม และต้องกดรับทราบที่เว็บหรือที่ปุ่มบนบอร์ด)

ข้อ ก. ขัดกับ spec ปัจจุบันที่เขียนว่า "gate closing clears" จึงต้องแก้ spec ด้วย

## 2. [สูง] การแจ้งเตือนบนเว็บรับรู้ช้าและหลุดง่าย (ข้อ 1.4)

- ถ้าอยู่หน้าอื่น วงแดงที่เมนูขึ้นช้า หน้าเว็บดึงสรุปทุก 10 วินาที (`ALARM_SUMMARY_POLL_MS = 10000`)
- ผู้ใช้เสนอให้มี**กระดิ่งแจ้งเตือน** ที่เข้าถึงง่ายทั้งในคอมและมือถือ อัปเดตเร็ว และ**จุดแดงต้องไม่หายเอง**จนกว่าจะกดเปิดดู
- เหตุวิกฤตควรมีการแจ้งที่หนักกว่านี้ ตัวเลือกคือแบนเนอร์เต็มจอที่ต้องกดปิด เสียงจากเบราว์เซอร์ หรือ buzzer บนบอร์ดถ้ามีฮาร์ดแวร์

## 3. [กลาง] LED บอกแค่วิกฤต (ข้อ 3.1 และ 4.3)

- ตอนนี้ LED กระพริบแดงเฉพาะเมื่อมีเหตุ**วิกฤต**ที่ยังไม่รับทราบ (`critical_unacked > 0` ใน `app_main.c`) ระดับเตือนและข้อมูลยังเป็นเขียวปกติ
- ผู้ใช้เสนอ: เตือนที่ยังไม่รับทราบเป็นเหลืองค้าง ระดับข้อมูลเป็นน้ำเงินค้าง
- ต้องตัดสินว่าแต่ละสีทับสถานะ LED เดิม (AP on/off, staging, การกดปุ่ม) อย่างไร และหลังรับทราบแล้วสีจะเป็นอย่างไร

## 4. [กลาง] คำในเงื่อนไขของสัญญาณแบบ ใช่/ไม่ใช่ อ่านซ้ำซ้อน (ข้อ 6.1)

- ตัวอย่าง: "รีเลย์ 1 (ปั๊มน้ำ) เปิด" ตามด้วย "เปิด" หรือ "ลูกลอยลอย" ตามด้วย "เปิด"
- สาเหตุคือชื่อสัญญาณเป็นประโยคอยู่แล้ว แต่ค่าถูกแสดงเป็น เปิด/ปิด
- ทางแก้คือแสดงค่าของสัญญาณ bool เป็น **ใช่/ไม่ใช่** ทั้งในเงื่อนไข "เฉพาะตอน" ช่อง "ค่าตอนนี้" และคอลัมน์ค่าในประวัติ หรือเปลี่ยนชื่อสัญญาณให้เป็นคำนามแล้วใช้ค่าคู่ที่เหมาะกับแต่ละตัว เช่น รีเลย์ 1 = เปิด/ปิด, ลูกลอย = ลอย/จม

## 5. [กลาง] ข้อ 8 (ความปลอดภัยของ API) ยังไม่ได้ทดสอบจริง เพราะคำสั่งใน checklist ใช้ใน PowerShell ไม่ได้

- 6 คำสั่งแรกของ 8.1 ผ่าน
- 3 คำสั่งล่างของ 8.1, ทั้งหมดของ 8.2 และ 8.3 **ไม่ได้ถึงบอร์ด** หรือถึงแต่ผิดรูป เห็นได้จากข้อความ `curl: (3) unmatched close brace` และ `URL rejected: Port number`
- PowerShell ตัดเครื่องหมาย `\"` ในข้อมูล JSON ก่อนส่งให้ `curl.exe` ทำให้ login ได้ `missing_fields` ไม่มี cookie และ 8.3 จึงได้ 401 แทน 400
- ต้องแก้ checklist ให้ส่ง JSON ผ่านไฟล์ (`-d "@body.json"`) หรือใช้ `Invoke-WebRequest` แล้วให้ผู้ใช้ทดสอบข้อ 8 ใหม่
- ในบันทึกมีคำว่า `<รหัสผ่านของคุณ>` ติดมาด้วย ต้องแทนด้วยรหัสจริงตอนทดสอบ

## 6. [ต่ำ] log ตอนบูตและ log ซ้ำ (ข้อ 10)

- `pump 2 PZEM FAULT`: แก้แล้วใน commit `3419029` จะขึ้นเป็น `chiller PZEM FAULT` หลัง flash ครั้งถัดไป
- `PT100 sensor fault: N consecutive failures`: ขึ้นเป็น **warning ทุก 1 วินาทีไม่หยุด** ตลอดเวลาที่ PT100 เสีย (`cooling_control.c:262`) เป็นโค้ดเดิมก่อน branch นี้ ควรเปลี่ยนเป็น log ครั้งเดียวตอนเริ่มเสียและตอนกลับมา แบบเดียวกับ PZEM
- `E task_wdt: TWDT already initialized`: บรรทัด error ตอนบูต ตามด้วย `TWDT reconfigured` ซึ่งทำงานถูกต้อง เป็นโค้ดเดิม แต่ระดับ E ทำให้ดูเหมือนมีปัญหา
- MAX31865 ไม่พบชิป: ถูกต้อง เพราะไม่ได้ต่อเซนเซอร์
- heap นิ่ง (`heap_free` 175,596 → 171,460 → 171,472 → 171,468) และ `tasks=19` ผ่าน
