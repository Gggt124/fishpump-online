# คู่มือทดสอบบนบอร์ด: PZEM-004T x2 + SEN0708 pH

Firmware: `firmware/esp32s3-dev` @ `e9ea4ec` (flash ลง COM12 แล้วเมื่อ 2026-11-14)
ผลที่ทดสอบผ่าน serial ไปแล้ว: บูตใน 0.9 s, fault ที่ 5.0–5.9 s, heap คงที่, ไม่มี crash

> เปิดไฟล์นี้ไว้ก่อนต่อ Wi-Fi ของบอร์ด เพราะตอนต่อแล้ว PC จะไม่มีอินเทอร์เน็ต
> log ดูได้ที่พอร์ต **USB (COM12)** ด้วยคำสั่ง `idf.py -C firmware -p COM12 monitor` ไม่ใช่พอร์ต UART

## ส่วน A — ทดสอบได้เลย ไม่ต้องต่อเซนเซอร์

### A1. เตรียม
- [/] ต่อ PC หรือมือถือเข้า Wi-Fi `FishPump-Setup`
- [/] เปิด `http://192.168.4.1` แล้ว login (`admin`)

### A2. หน้าเว็บและเมนู
- [/] ตอน logout อยู่ เปิด `http://192.168.4.1/sensors` แล้วต้องเด้งไปหน้า login
- [/] หลัง login มีเมนู **"เซนเซอร์"** อยู่ใต้ "ระบบทำความเย็น" (บนมือถืออยู่ในเมนู "เพิ่มเติม")
- [/] กดรีเฟรช (F5) ตอนอยู่หน้า `/sensors` แล้วยังเปิดหน้าเซนเซอร์ได้ ไม่ขึ้น 404

### A3. หน้าเซนเซอร์ตอนไม่มีเซนเซอร์ (ผลที่ควรเป็น)
- [/] การ์ด **ไฟฟ้า ปั๊ม 1** และ **ปั๊ม 2** ขึ้นแถบแดง "เซนเซอร์ไม่ตอบ ตรวจสายสัญญาณ"
- [/] การ์ด **คุณภาพน้ำ** ขึ้นแถบแดง "เซนเซอร์ pH ไม่ตอบ ตรวจสาย RS485" และ badge ขึ้นว่า "ไม่มีสัญญาณ"
- [/] ตัวเลขทุกช่องเป็น 0 แบบสีจาง
- [/] ปุ่ม "รีเซ็ต kWh", "บันทึกจุดที่ 1/2" และปุ่มบันทึก offset **กดไม่ได้** (สีเทา)
- [/] บรรทัดบนสุด "อัปเดตล่าสุด HH:MM:SS" เปลี่ยนเวลาทุก ~5 วินาที

### A4. หน้า Hardware
- [/] มีกล่อง **"พินเซนเซอร์ UART"** 3 แถว:
  - PZEM-004T ปั๊ม 1 — UART0 · TX GPIO 4 · RX GPIO 42 · 9600 bps
  - PZEM-004T ปั๊ม 2 — UART1 · TX GPIO 40 · RX GPIO 41 · 9600 bps
  - RS485 pH (SEN0708) — UART2 · TX GPIO 21 · RX GPIO 14 · 4800 bps
- [/] ส่วนเลือกพิน GPIO แบบเดิมยังทำงานปกติ

### A5. ระบบเดิมไม่พัง
- [/] หน้าแผงควบคุม: สั่ง start/stop ปั๊มได้เหมือนเดิม และรีเลย์ทำงาน
- [/] หน้าระบบทำความเย็นเปิดได้ปกติ (PT100 ขึ้น fault เพราะยังไม่ได้ต่อ ซึ่งเป็นแบบนี้มาตั้งแต่ก่อนงานนี้)

### A6. SSE stream
- [/] เปิดแท็บใหม่ไปที่ `http://192.168.4.1/api/events`
- [/] ทุก ~2 วินาทีต้องเห็นข้อความประมาณนี้:
  ```
  event: power
  data: {"ch":0,"valid":false,"fault":true,"v":0.0,"a":0.000,...}
  event: power
  data: {"ch":1,"valid":false,"fault":true,...}
  ```

### A7. Red test ของ API (ยิงข้อมูลเสีย)
ทดสอบนี้ **ปลอดภัยตอนไม่มีเซนเซอร์** เพราะไม่มีอะไรถูกเขียนลงเซนเซอร์
**ห้ามรันตอนต่อ SEN0708 อยู่** เพราะในชุดมีคำสั่งตั้ง pH offset = 0 ซึ่งจะเขียนลงเซนเซอร์จริง

1. [/] Login ที่ `http://192.168.4.1` แล้วกด **F12 → Console**
2. [/] วางโค้ดนี้แล้วกด Enter:

```js
(async () => {
  const cases = [
    ['/api/power/reset-energy', '{}', 400],
    ['/api/power/reset-energy', '{"channel":2}', 400],
    ['/api/power/reset-energy', '{"channel":"0"}', 400],
    ['/api/water/calibrate', '{"point":3,"buffer_ph":4}', 400],
    ['/api/water/calibrate', '{"point":1,"buffer_ph":1e9}', 400],
    ['/api/water/calibrate', '{"point":1}', 400],
    ['/api/water/offset', '{"ph_offset":5}', 400],
    ['/api/water/offset', '{"temp_offset":-11}', 400],
    ['/api/water/offset', '{"ph_offset":0.1,"temp_offset":1}', 400],
    ['/api/water/offset', 'not json', 400],
    ['/api/power/reset-energy', '{"channel":0}', 202],
    ['/api/water/calibrate/cancel', '', 202],
    ['/api/water/offset', '{"ph_offset":0}', 202],
  ];
  const rows = [];
  for (const [url, body, want] of cases) {
    const r = await fetch(url, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body });
    const j = await r.json().catch(() => ({}));
    rows.push({ url, body, want, got: r.status, error: j.error || '', ok: r.status === want ? 'PASS' : 'FAIL' });
  }
  console.table(rows);
  // Spam: ส่ง 10 คำสั่งพร้อมกัน ต้องได้ 202 หรือ 503 queue_full และบอร์ดต้องไม่ค้าง
  const spam = await Promise.all(Array.from({ length: 10 }, () =>
    fetch('/api/water/calibrate/cancel', { method: 'POST', body: '' }).then(r => r.status)));
  console.log('spam statuses:', spam.join(','));
  const st = await (await fetch('/api/sensors/status')).json();
  console.log('power_notice:', st.power_notice.text, '| water notice:', st.water.notice.text);
})();
```

- [/] ตารางขึ้น **PASS ทุกแถว**
- [/] `spam statuses` มีแต่ `202` หรือ `503` (ไม่มี 500 และไม่ timeout) และหน้าเว็บยังใช้ต่อได้
- [/] `power_notice` ขึ้นว่า "ปั๊ม 1: เซนเซอร์ไม่ตอบ รีเซ็ต kWh ไม่ได้"
- [/] `water notice` เป็นข้อความเกี่ยวกับยกเลิกหรือเซนเซอร์ไม่ตอบ

### A8. ไม่ได้ login ต้องโดนปฏิเสธ

### A9. Wi-Fi หลุดแล้วกลับมา
- [/] เปิดหน้าเซนเซอร์ค้างไว้ ปิด Wi-Fi ของ PC ประมาณ 10 วินาที แล้วต่อ `FishPump-Setup` ใหม่
- [/] ภายใน ~10 วินาที "อัปเดตล่าสุด" กลับมาเดินเอง **โดยไม่ต้องกดรีเฟรช**

### A10. Serial (ถ้าสะดวก)
- [ ] `idf.py -C firmware -p COM12 monitor` แล้วกดปุ่ม RESET บนบอร์ด
- [ ] เห็น `System Ready` ภายใน ~1 s
- [ ] ที่ ~5–6 s เห็น 3 บรรทัด: `water_quality: SEN0708 FAULT`, `power_monitor: pump 1 PZEM FAULT`, `pump 2 PZEM FAULT`
- [ ] ไม่มี `Guru Meditation`, `abort` หรือ `Task watchdog got triggered`

## ส่วน B — ตอนต่อเซนเซอร์แล้ว

### การต่อสาย
| UART | ESP32 TX | ESP32 RX | อุปกรณ์ |
|---|---|---|---|
| UART0 | GPIO 4 | GPIO 42 | PZEM-004T ปั๊ม 1 (ต่อเหมือนตอนทดสอบในโปรเจกต์ pzem004t) |
| UART1 | GPIO 40 | GPIO 41 | PZEM-004T ปั๊ม 2 |
| UART2 | GPIO 21 | GPIO 14 | RS485_TTL → SEN0708 |

**SEN0708 / RS485_TTL** (ตามสเปกโปรเจกต์ sen0708):
- โมดูล RS485_TTL ต้องใช้ **VCC 3.3 V ห้ามใช้ 5 V** เพราะ GPIO14 ทนแรงดัน 5 V ไม่ได้
- TXD → GPIO14, RXD → GPIO21
- A → สายเหลืองของ SEN0708, B → สายเส้นที่ 4, ⏚ → สายดำของ SEN0708 และ 0 V ของแหล่งจ่าย 12 V
- สายน้ำตาลของ SEN0708 ต่อ +12 V (ใช้ได้ 10–30 V)
- ถ้าเซนเซอร์ไม่ตอบ ให้ลองสลับ TXD/RXD ก่อน แล้วค่อยลองสลับ A/B

### B1. PZEM
- [ ] ต่อเสร็จแล้ว ภายใน ~2 วินาทีแถบแดงของการ์ดนั้นต้องหายไป และตัวเลขขึ้นเป็นค่าปกติ (ไม่จาง)
- [ ] เปิดปั๊ม 1 อย่างเดียว: กระแสการ์ดปั๊ม 1 ขึ้น ส่วนปั๊ม 2 ใกล้ 0
- [ ] สลับเปิดปั๊ม 2 อย่างเดียว: ผลต้องกลับกัน
  - **ถ้ากระแสขึ้นผิดการ์ด** แปลว่าสลับสาย UART0 กับ UART1
- [ ] ค่า V ~220–230, Hz ~50, PF อยู่ในช่วง 0–1
- [ ] ถอดสาย PZEM ปั๊ม 2 ออก: **เฉพาะการ์ด 2** ต้องขึ้นแดงภายใน ~6 s ส่วนการ์ด 1 ต้องยังปกติ เสียบกลับแล้วต้องหาย
- [ ] กด "รีเซ็ต kWh" ของปั๊มที่ต่ออยู่ → ยืนยัน → ข้อความ "ปั๊ม N: รีเซ็ต kWh แล้ว" และค่า kWh กลับเป็น 0

### B2. SEN0708
- [ ] แถบแดงหายไป และค่า pH กับอุณหภูมิน้ำขึ้นเป็นค่าที่สมเหตุสมผล
- [ ] จุ่มในน้ำนิ่งๆ แล้ว badge เปลี่ยนเป็น **"ค่านิ่ง"** ภายใน ~10 s และปุ่มคาลิเบรตกดได้
- [ ] **Red test ที่ต้องโดนปฏิเสธ** (ข้อความต้องขึ้นใต้การ์ดคาลิเบรต):
  - [ ] กด "บันทึกจุดที่ 2" ก่อนจุดที่ 1 → "ต้องทำจุดที่ 1 ก่อน"
  - [ ] ใส่ 6.86 ในช่องจุดที่ 1 แล้วกด → "ค่าน้ำยาบัฟเฟอร์อยู่นอกช่วงของจุดนี้"
  - [ ] กดขณะกำลังขยับหัววัด (badge ขึ้น "กำลังนิ่ง...") → ปุ่มต้องกดไม่ได้
- [ ] **คาลิเบรตจริง:**
  1. [ ] น้ำยา pH 4.01 → รอจนนิ่ง → กด "บันทึกจุดที่ 1" → ข้อความ "บันทึกจุดที่ 1 = pH 4.01 แล้ว" และสถานะเปลี่ยนเป็น "รอจุดที่ 2"
  2. [ ] ล้างหัววัด → น้ำยา pH 9.18 → รอจนนิ่ง → กด "บันทึกจุดที่ 2" → สถานะ "คาลิเบรตเสร็จ"
  3. [ ] จุ่มน้ำยา pH 6.86 → ค่าที่อ่านได้ควรอยู่ราว 6.86 ±0.05
- [ ] **Offset:** ตั้ง pH offset +0.10 → ค่า pH ต้องขยับขึ้นประมาณ 0.10 → กด "รีเซ็ตเป็น 0" → ค่ากลับเหมือนเดิม
- [ ] ถอดสาย A/B ออก → ภายใน ~6 s ขึ้นแถบแดง เสียบกลับแล้วต้องหาย
