## 3. การตัดสินใจระหว่างทำ (Ruling) เรียงตามเวลา

ผู้ใช้สั่งให้ทำต่อเนื่องจนจบโดยไม่หยุดถาม การตัดสินใจที่ spec ระบุ "(Claude ตัดสิน)" ก็เป็นของผู้ทำงาน แก้กลับได้ แต่ละข้อมีต้นทุนถ้าผิดตามที่บันทึกใน ledger

**ตัดสินใจใน spec (ผลที่เห็นตอน bench)**
- ค่าของสัญญาณ bool แสดงเป็น **ใช่/ไม่ใช่** ทุกที่ในหน้าแจ้งเตือน
- ข้อ "ต้องตัดสินใจ" (รีวิวข้อ 3): สัญญาณหายต่อเนื่อง **≥ 5 วินาที** ทำให้กฎที่ PENDING เริ่มนับใหม่ พลาดครั้งเดียวไม่เปลี่ยนอะไรตามเดิม ส่วน ACTIVE/LATCHED ไม่ถูกแตะ
- LED: วิกฤตแดงกระพริบ > เตือนเหลืองค้าง > ข้อมูลน้ำเงินค้าง > เขียว AP เปิด โดยสถานะปุ่ม, recovery AP, factory reset, staging ทับเสมอ
- เหตุการณ์ที่ไม่มีเวลาจริง: ถือไว้ใน ring ไม่ส่ง (ดูข้อกำหนดด้านล่าง)

**ตัดสินใจระหว่างทำ**
1. **Pre-flight / T2:** test กรณี record เล็กลงยอมให้อ่อน (ผลเป็น false หรือชุดกฎที่ตรวจผ่านทั้งหมด) เพราะ spec ต้องการแค่ไม่อ่านเกินและกฎที่ได้ต้องใช้ได้ — ต้นทุนถ้าผิด: test อ่อนลง
2. **Pre-flight:** ไม่ทำรีวิวข้อ 9 ซ้ำ เพราะ `alarm_engine_init` ลบ mutex ทั้งสองเมื่อสร้าง task ไม่ได้อยู่แล้ว (ตรวจที่ `alarm_engine.c:216-222`) — ต้นทุนถ้าผิด: ไม่มี
3. **Pre-flight:** `POST /api/protection` ไม่เช็ก `is_password_default` เพราะ POST ของแจ้งเตือนก็ไม่เช็ก — ต้นทุนถ้าผิด: เช็กเพิ่มหนึ่งจุด
4. **Task 2:** ยกข้อเสนอแนะ Minor 1 ของผู้ตรวจ (v1 decode ใช้ `sizeof(alarm_rule_t)`) เป็น **Important** เพราะเมื่อ struct โตขึ้น blob v1 ที่ไม่เคยบันทึกใหม่จะอ่านไม่ได้และกฎของคุณหาย ซึ่งคือความล้มเหลวที่ task นี้มีไว้กัน → เพิ่ม `ALARM_BLOB_V1_REC_SIZE` + static assert (`2655d89`) — ต้นทุนถ้าผิด: ค่าคงที่หนึ่งตัว
5. **Task 3 (รอบ 1):** ยกข้อ "ถือเหตุการณ์ไม่มีเพดานเวลา ถ้า SNTP ไม่ติดเหตุวิกฤตจะค้างตลอด" เป็น **Important** เพราะการแจ้งเตือนคือจุดประสงค์ของแพลตฟอร์ม → เพิ่ม `UPLINK_CLOCK_HOLD_MAX_MS = 120000` — ต้นทุนถ้าผิด: พารามิเตอร์เพิ่มหนึ่งตัว
6. **Task 3 (รอบ 1):** รวมข้อเล็กราคาถูก 3 ข้อในรอบเดียว (ขยายคอมเมนต์สัญญา `set_sink`, ใช้ `max(pending, n)`, log ครั้งเดียวตอนเริ่ม/จบการถือ) — ต้นทุน: เล็กน้อย
7. **Task 3 (รอบ 2):** ยกข้อ "sink กระพริบแล้วรีเซ็ตตัวจับเวลา/latch ทำให้เพดาน 120 วินาทีไม่ทำงานเมื่อ SNTP ไม่ติด" และ "`hold_active` ค้างเมื่อ n==0" เป็น **Important** (ความล้มเหลวเดียวกับข้อ 5) → จุดเริ่มถือและ latch รอด sink หลุด รีเซ็ตเฉพาะเมื่อนาฬิกาถูกตั้ง, สกัดเป็นฟังก์ชันบริสุทธิ์พร้อม self-test — ต้นทุนถ้าผิด: ไม่กี่บรรทัด
8. **Task 6:** spec §5 ว่า error ของ `measure_start` ที่ไม่รู้จักตอบ 503 `measure_unavailable` แต่ plan/brief ว่า 503 `unavailable` — เก็บ `unavailable` (รหัสเดียวกับ 503 อื่น และสาขานี้เข้าไม่ถึงตอนนี้) — ต้นทุนถ้าผิด: เปลี่ยนสตริงเดียว
9. **Task 7:** ป้ายช่องตามที่ brief เขียนอ่านเป็นวงเล็บซ้อน → ให้ Task 8 แก้เป็น `(วินาที, 1–600)` ฯลฯ พร้อมผ่อน verify — ต้นทุน: ไม่มี (เป็นเรื่องข้อความ)

**ข้อกำหนดที่คุณควรรู้จากการตัดสินใจเหล่านี้**
- ถือเหตุการณ์สูงสุด 120 วินาทีเมื่อไม่มีเวลาจริง แล้วส่งโดยไม่มี `ts` (หรือส่งเลยเมื่อค้างใกล้เต็ม 24 จาก 32) เวลาที่ sink หลุดนับรวมในเพดาน
- จำนวนบนกระดิ่งนับ "ยังไม่เห็น + active" จึงไม่เหลือ 0 ทันทีหลังเปิดถ้ายังมีแจ้งเตือน active (เหมือนป้ายที่เมนู)
- เสียงเตือนต้องมีการคลิกหน้าเว็บหนึ่งครั้งก่อน (นโยบาย autoplay ของเบราว์เซอร์) และเสียงทำงานเฉพาะตอนเปิดหน้าเว็บอยู่

## 5. สิ่งที่ยังไม่ได้พิสูจน์บนฮาร์ดแวร์

ทั้งหมดต่อไปนี้ผ่านเฉพาะการตรวจโค้ด/self-test/review รอ bench ตาม `docs/bench-test-pre-mqtt.md`:

- **Boot log:** ไม่มีบรรทัด `E task_wdt` และมี `TWDT reconfigured` (แก้โดยเรียก `esp_task_wdt_reconfigure` ตรง ไม่เรียก `esp_task_wdt_init`) · PT100 ไม่ต่อ log WARN ครั้งเดียว
- **HWM:** `hwm_alarm`, `hwm_uplink`, `hwm_dry_run` ใน `[BOARD_DIAG]` (เกณฑ์ > 512 ไบต์ แต่ละตัว; -1 = task ไม่ถูกสร้าง) ยังไม่เคยอ่านค่า รวมถึง stack 4096 ของ `dry_run_guard` ที่ค้างมาจากรอบเดินแห้ง ซึ่งตอนนี้วัดได้แล้ว หลังรัน path ที่ใช้ stack มากอย่างน้อยหนึ่งครั้ง
- **blob v1 → v2:** ทดสอบด้วย blob ที่สร้างเองใน self-test เท่านั้น ยังไม่เคยอ่าน NVS จริงของคุณ (บูตแรกหลัง flash ต้องขึ้น `storage saved`)
- **Uplink:** ไม่มี transport จึงทดสอบการถือเหตุการณ์/เพดาน 120 วินาที/การรอด sink หลุดกับตัวส่งจริงไม่ได้ (มีเฉพาะ self-test ของฟังก์ชันบริสุทธิ์และการตรวจ lock แบบ static) ดูได้เฉพาะ `waiting_for_clock` ใน preview
- **LED:** สีและลำดับความสำคัญจริงบนบอร์ด (ตรวจแค่ลำดับในโค้ดและฟังก์ชันระดับที่ตรวจใน QEMU)
- **เว็บ:** กระดิ่ง จำนวนที่ค้างข้ามหน้า/รีโหลด จุดแดงเมนูมือถือ ชื่อแท็บ `(n)` overlay วิกฤต "ปิดไว้ก่อน" ไม่เด้งกลับ เหตุใหม่เปิดซ้ำ เสียงหลังคลิกและสวิตช์ปิดเสียง การหยุด poll ตอนแท็บซ่อน ยังไม่ได้ลองในเบราว์เซอร์จริง
