# คีย์ OTA: สร้าง สำรอง ตรวจ เปลี่ยน

## คีย์นี้ทำอะไร และไม่ทำอะไร

- คีย์คือ AES-256 (hex 64 ตัว) ใช้เข้ารหัสไฟล์สำหรับ **web OTA** (`POST /api/ota`): ไฟล์ = IV 16 ไบต์ + AES-256-CTR ของ image
- มันช่วยปกปิดไฟล์ขณะส่ง และกันคนที่ไม่มีคีย์อัปโหลดไฟล์มั่ว
- มัน**ไม่ใช่เกราะป้องกันจริง**: คีย์ฝังอยู่ใน flash ที่ไม่ได้เข้ารหัส ใครมีบอร์ดในมือดึงออกได้ และการเข้ารหัสไม่ใช่ลายเซ็น (ใครมีคีย์ก็สร้างไฟล์ที่บอร์ดรับได้) ถ้าจะขายหลายลูกค้า ต้องใช้ secure boot และ image ที่เซ็นลายเซ็น (ยังไม่ทำ อยู่ใน backlog)
- คีย์เดียวใช้ทั้งฝูงบอร์ด รั่วทีเดียวรั่วหมด
- ThingsBoard OTA **ไม่ใช้คีย์นี้** (ส่งไฟล์ธรรมดา) ความลับของเส้นทางนั้นต้องแก้ด้วย TLS ตอนขึ้น VPS

## คีย์ dev กับคีย์ release

- build ปกติ (dev) ถ้าไม่มี `secrets.h` จะใช้คีย์ศูนย์ทั้งหมด ลายนิ้วมือ **`66687aad`** และ `ota_key_dev` เป็น true
- build release (`-DFISHPUMP_RELEASE=ON`, CI ตั้งให้เอง) ล้มตอน configure ถ้า `secrets.h` ไม่มี คีย์ไม่ครบ 64 ตัว เป็นค่าตัวอย่าง หรือเป็นศูนย์ทั้งหมด ข้อความ error ไม่แสดงตัวคีย์

## สร้างคีย์

```powershell
python firmware/scripts/write_secrets.py --generate
```

(หรือ `firmware/scripts/generate_secrets.ps1` ซึ่งเรียกอันเดิม) สคริปต์เขียน `firmware/components/app_config/secrets.h` และพิมพ์**เฉพาะ path กับลายนิ้วมือ** ไม่พิมพ์ตัวคีย์ ถ้าไฟล์มีอยู่แล้วจะไม่เขียนทับ (ใส่ `--force` ถ้าตั้งใจ แต่คีย์เก่าจะหาย) และปฏิเสธคีย์ศูนย์

จากนั้น**สำรองสองที่เสมอ**:

1. GitHub secret ชื่อ `OTA_ENCRYPTION_KEY` (Settings > Secrets and variables > Actions) ค่าคือตัวคีย์ hex 64 ตัวจากไฟล์ `secrets.h` (ช่องว่าง/ขึ้นบรรทัดใหม่ท้ายค่าไม่เป็นไร เครื่องมือตัดให้)
2. ที่เก็บนอก GitHub: โปรแกรมจัดการรหัสผ่านหรือที่เก็บออฟไลน์

repo นี้อยู่ใน OneDrive ถ้าเป็นไปได้ให้ build release บนเครื่องที่ไม่ซิงก์โฟลเดอร์นั้น หรือลบ `secrets.h` ออกหลังสำรองแล้ว (build จริงใช้ CI อยู่แล้ว)

## ตรวจว่าบอร์ดใช้คีย์ไหน

เทียบ "ลายนิ้วมือ" (8 ตัวแรกของ SHA-256 ของคีย์ดิบ 32 ไบต์):

- log บูต: บรรทัด `OTA key fp=<fp> (dev|release)`
- `status.get` (หน้า/เครื่องมือเว็บ): ฟิลด์ `ota_key_fp` และ `ota_key_dev`
- ThingsBoard: attribute `tb_link.ota_key_fp` และ `tb_link.ota_key_dev`
- ชื่อไฟล์ release: `fishpump-<ver>-<fp>.ota.bin` และบรรทัดสุดท้ายของ log ตอน package

ลายนิ้วมือของบอร์ดต้องเท่ากับของไฟล์ ถ้าไม่เท่า ไฟล์ web OTA จะถอดรหัสไม่ได้

## ย้ายบอร์ดจากคีย์ศูนย์เป็นคีย์จริง (ทำครั้งเดียวต่อบอร์ด)

บอร์ดบนโต๊ะตอนนี้ใช้คีย์ศูนย์ (build เดิมไม่มี `secrets.h`) ย้ายโดยไม่ต้องต่อสาย:

1. ตั้งคีย์จริงใน GitHub secret แล้ว push tag release (ดู [`release.md`](release.md)) ได้ไฟล์ `fishpump-<ver>.bin` (ธรรมดา) และ `.ota.bin`
2. **เข้ารหัสไฟล์ธรรมดาด้วยคีย์ศูนย์** (ไม่ใช่ใช้ไฟล์ `.ota.bin` ที่เข้ารหัสด้วยคีย์ใหม่) ตั้งตัวแปรสภาพแวดล้อมเป็นเลข 0 จำนวน 64 ตัว แล้วรัน
   `python firmware/scripts/encrypt_ota.py fishpump-<ver>.bin migrate.ota.bin --key-env ชื่อตัวแปร`
3. อัปโหลด `migrate.ota.bin` ทาง web OTA (หน้าเว็บของบอร์ด) หรือจะอัปโหลดไฟล์ธรรมดา `fishpump-<ver>.bin` ผ่าน ThingsBoard OTA ก็ได้ (ไม่ถอดรหัส)
   - **บอร์ดที่รัน firmware ที่ build ก่อน release pipeline (เช่นบอร์ดที่ติดป้าย 0.3.2 หรือ 0.4.0 จาก PR #1) ใช้ทางเว็บไม่ได้:** firmware เก่ามีเพดาน upload 1,966,080 ไบต์ เล็กกว่า image ปัจจุบัน (~2.06 MB) จะได้ 413 ให้ใช้ ThingsBoard OTA หรือต่อสายแฟลชแทน (bench 2026-11-22 ย้ายบอร์ดด้วย ThingsBoard OTA สำเร็จ)
4. บอร์ดรีบูตพร้อมคีย์ใหม่ ตรวจว่า `ota_key_fp` เท่ากับลายนิ้วมือใน release และ `ota_key_dev` เป็น false

## เปลี่ยนคีย์ในอนาคต

ใช้กลไกเดียวกัน: build รุ่นที่ฝังคีย์ใหม่ แล้วเข้ารหัสไฟล์นั้นด้วย **คีย์เก่า** อัปเดตทีละบอร์ด เมื่อทุกบอร์ดรายงานลายนิ้วมือใหม่แล้วจึงเลิกใช้คีย์เก่า อย่าเปลี่ยน GitHub secret ก่อนบอร์ดครบ ถ้าบอร์ดไหนยังใช้คีย์เก่าอยู่ ต้องเก็บคีย์เก่าไว้ใช้เข้ารหัสไฟล์ให้บอร์ดนั้น

## คีย์หาย

ถ้าไม่มีคีย์ที่บอร์ดใช้อยู่ จะอัปเดตทางเว็บไม่ได้ ทางออกคือต่อสาย USB แล้วแฟลช `fishpump-<ver>-factory.bin` (หรือใช้ `FLASH.bat` จาก `flash-package.zip`) ซึ่งล้างบอร์ด แล้วบอร์ดจะได้คีย์ของ build นั้น
