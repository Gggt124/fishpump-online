## 1. Flow switch (ข้อ 0 ใน spec §6)

ต่อสาย: **GPIO 9 → สวิตช์ (ขา NO) → GND** (ถ้ายังไม่มีสวิตช์จริง ใช้สายจัมเปอร์แตะ GPIO 9 กับ GND แทน)

1. **ทำ:** เปิดหน้า **เซนเซอร์** ตอน GPIO 9 ปล่อยลอย
   **ต้องเห็น:** การ์ด **"การไหลของน้ำ"** ขึ้น **"ไม่ไหล"**
   - [ ] ผ่าน  บันทึก: ______________________
2. **ทำ:** ใช้จัมเปอร์ต่อ GPIO 9 เข้า GND ค้างไว้
   **ต้องเห็น:** หลังประมาณ **1 วินาที** ขึ้น **"ไหล"**
   - [ ] ผ่าน  บันทึก: ______________________
3. **ทำ:** แตะจัมเปอร์เข้า-ออกเร็วๆ (สั้นกว่า 1 วินาที) หลายครั้งตอนสถานะเป็น "ไม่ไหล"
   **ต้องเห็น:** การ์ด **ไม่เปลี่ยน** (กันสวิตช์สั่น)
   - [ ] ผ่าน  บันทึก: ______________________
4. **ทำ:** ไปหน้า **แจ้งเตือน** → เปิดสวิตช์ของ preset **"ปั๊มน้ำเปิดแต่น้ำไม่ไหล"** → ไปหน้า **แผงควบคุม** สั่ง **start ปั๊มน้ำ (รีเลย์ 1)** โดยถอดจัมเปอร์ออก

## 4. กฎทดสอบด้วย `uptime_sec` (ข้อ 3)

ใช้ค่า "เวลาทำงาน (uptime_sec)" ของบอร์ดเป็นสัญญาณทดสอบ เพราะเพิ่มขึ้นเองตลอด ไม่ต้องมีเซนเซอร์

1. **ทำ:** กด **+ เพิ่มกฎ** ตั้งค่า: ชื่อ `ทดสอบ uptime`, ค่าที่ตรวจ **เวลาทำงาน**, เงื่อนไข **มากกว่า**, ค่าที่กำหนด = (uptime ที่ช่อง "ค่าตอนนี้" + 60), ต้องเกินนาน **5** วินาที, ระดับ **วิกฤต** → บันทึก
   **ต้องเห็น:** ช่อง "ค่าตอนนี้" ในหน้าต่างแสดงตัวเลข uptime ที่เพิ่มทุก 2 วินาที
   - [ ] ผ่าน  บันทึก: ______________________
2. **ทำ:** รอ
   **ต้องเห็น:** ที่ประมาณ **60 + 5 วินาที** รายการ "ทดสอบ uptime" ขึ้นเป็นสี **แดง (วิกฤต)** และ **LED กระพริบแดง 1 Hz** (ทั้ง LED บนบอร์ดและ LED ภายนอก)
   - [ ] ผ่าน  บันทึก: ______________________
3. **ทำ:** แก้ระดับของกฎนี้เป็น **เตือน** แล้วบันทึก, แก้เป็น **ข้อมูล** แล้วบันทึกอีกครั้ง
   **ต้องเห็น:** (หลังแก้กฎ รายการเดิมหายเพราะสถานะถูกรีเซ็ต แล้วเกิดใหม่ตามดีเลย์) สีป้ายเปลี่ยน แดง → เหลือง → ฟ้า และเมื่อไม่ใช่วิกฤต LED **ไม่กระพริบ**
   - [ ] ผ่าน  บันทึก: ______________________

## 8. ไม่ login แล้วเรียก API ต้องถูกปฏิเสธ (ข้อ 7)

ทำจาก PowerShell/เทอร์มินัลที่ต่อ Wi-Fi ของบอร์ดอยู่ (`curl.exe` ใน PowerShell)

**8.1 ยังไม่ login → ต้องได้ `401`** (ใส่ `Origin` ที่ถูกต้องเสมอ เพื่อไม่ให้ไปชนผลข้อ 403)

```bash
curl.exe -i http://192.168.4.1/api/alarms/signals
curl.exe -i http://192.168.4.1/api/alarms/values
curl.exe -i http://192.168.4.1/api/alarms/rules
curl.exe -i http://192.168.4.1/api/alarms/status
curl.exe -i http://192.168.4.1/api/alarms/summary
curl.exe -i http://192.168.4.1/api/uplink/preview
curl.exe -i -X POST -H "Content-Type: application/json" -H "Origin: http://192.168.4.1" -d "{\"all\":true}" http://192.168.4.1/api/alarms/ack
curl.exe -i -X POST -H "Content-Type: application/json" -H "Origin: http://192.168.4.1" -d "{\"id\":1}" http://192.168.4.1/api/alarms/rules/delete
curl.exe -i -X POST -H "Content-Type: application/json" -H "Origin: http://192.168.4.1" -d "{\"name\":\"x\"}" http://192.168.4.1/api/alarms/rules
```

- [ ] ทั้ง 9 คำสั่งขึ้น `HTTP/1.1 401` และ body `{"ok":false,"error":"unauthorized"}`
- [ ] เปิด `http://192.168.4.1/alarms` ตอน logout แล้วเด้งไปหน้า login

**8.2 login แล้วแต่ `Origin` ไม่ตรง → ต้องได้ `403`**

```bash
curl.exe -c jar.txt -X POST -H "Content-Type: application/json" -H "Origin: http://192.168.4.1" -d "{\"username\":\"admin\",\"password\":\"<รหัสผ่านของคุณ>\"}" http://192.168.4.1/api/login
curl.exe -i -b jar.txt -X POST -H "Content-Type: application/json" -H "Origin: http://evil.example" -d "{\"all\":true}" http://192.168.4.1/api/alarms/ack
curl.exe -i -b jar.txt -X POST -H "Content-Type: application/json" -H "Origin: http://evil.example" -d "{\"id\":1}" http://192.168.4.1/api/alarms/rules/delete
```

- [ ] สองคำสั่งหลังขึ้น `HTTP/1.1 403` (`forbidden`)

**8.3 login + Origin ถูกต้อง + ข้อมูลผิด → `400` พร้อมชื่อช่อง** (ไม่ควรเกิด 403)

```bash
curl.exe -i -b jar.txt -X POST -H "Content-Type: application/json" -H "Origin: http://192.168.4.1" -d "{\"name\":\"x\"}" http://192.168.4.1/api/alarms/rules
```

- [ ] ได้ `400` และ `"error":"missing_field"` `"message":"signal"`

## รอทดสอบกับอุปกรณ์จริง (หลัง sensor bench Part B)

ยังทำไม่ได้ตอนนี้ เพราะต้องมีปั๊มน้ำ, Chiller, หัว pH และสวิตช์น้ำไหลจริง

- [ ] pH ออกนอกช่วงจริง (เช่นจุ่มน้ำยาบัฟเฟอร์) → กฎ "pH ผิดช่วง" ขึ้น/หาย ตามเกณฑ์และช่วงกันสั่น
- [ ] รีเลย์ปั๊มน้ำค้าง: สั่งปิดรีเลย์ 1 แต่ปั๊มยังกินกระแส → กฎ "รีเลย์ปั๊มน้ำค้าง" ขึ้นแบบ latch (วิกฤต)
- [ ] วัดกระแสขณะปั๊มน้ำทำงานจริง เพื่อปรับเกณฑ์ preset **"ปั๊มน้ำไม่ทำงานตามคำสั่ง"** (ตอนนี้ตั้งชั่วคราวไว้ที่ < 0.3 A)
- [ ] วัดกำลังไฟ Chiller ตอนสั่งหยุด (standby) และตอนทำงานจริง เพื่อปรับเกณฑ์ preset **"Chiller ไม่ทำงานตามคำสั่ง"** (< 50 W) และ **"Chiller ทำงานทั้งที่สั่งหยุด"** (> 200 W)
- [ ] ปิดเบรกเกอร์ที่ Chiller แล้วดูว่า PZEM ตัวไหนหยุดตอบ (เพื่อรู้ว่ากฎ "มิเตอร์ไฟ Chiller ไม่ตอบ" ใช้ตรวจไฟดับได้ไหม)
- [ ] สวิตช์น้ำไหลจริงในท่อ: ขั้ว NO ปิดวงจรเมื่อน้ำไหล (ถ้าใช้ขั้ว NC ค่าจะกลับด้าน และเฟิร์มแวร์ไม่มีตัวเลือกกลับขั้ว)
- [ ] เพิ่มกฎ "กระแสปั๊มสูงเกิน" หลังรู้กระแสพิกัดของปั๊ม (preset ยังไม่มีข้อนี้)
