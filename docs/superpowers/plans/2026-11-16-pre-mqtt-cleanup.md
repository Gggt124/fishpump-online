# Pre-MQTT Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every firmware/web item that can be fixed without real sensors before the MQTT/ThingsBoard project: rounds A, C, D, review 3, and the user-facing dry-run minors. Record everything that needs hardware in one backlog file.

**Architecture:** Each fix stays inside its owning component. Pure logic goes into `alarm_rules` / `uplink_format` / `dry_run_logic` and is tested in the QEMU self-test. Glue changes in `main/`, `uplink`, `dry_run_guard` and the web UI are pinned by a new static-check script, `scripts/verify_pre_mqtt.py`.

**Tech Stack:** ESP-IDF v6.0.1 (C, FreeRTOS, `-Werror`), vanilla JS/HTML/CSS SPA served gzipped, Python 3 source-check scripts.

**Spec:** `docs/superpowers/specs/2026-11-16-pre-mqtt-cleanup-design.md`

## Global Constraints

**Environment and gates**
- Build environment (PowerShell): `. C:\Espressif\tools\Microsoft.v6.0.1.PowerShell_profile.ps1; Remove-Item Env:MSYSTEM -ErrorAction SilentlyContinue`. Run `idf.py` from `firmware/`. `-Werror` is on.
- Gates, from `firmware/`, all green before every commit:
  - `python scripts/verify_alarm_system.py` → `FAILED: 0`
  - `python scripts/verify_dry_run.py` → `FAILED: 0`
  - `python scripts/verify_sensor_integration.py` → exit 0
  - `python scripts/verify_pre_mqtt.py` → `FAILED: 0` (created in Task 1)
  - `powershell -File test/sensor_selftest/run_selftest.ps1` → `SELFTEST PASS`
  - `idf.py build` → succeeds with 0 warnings
  - `node --check main/static/app.js` → exit 0 (tasks touching JS)
- Long builds: redirect output to a log in `build/` and read its tail. The repo is on OneDrive, so never run recursive `find` over it.
- An existing verify check that a task's intended change breaks may be updated in the same commit. The report must name it and say why.

**Git**
- Never stage `firmware/.vscode/settings.json` or `docs/bench-test-alarms.md`. Both hold the user's local edits. Stage by explicit path only.
- Never use `git stash`, `git reset`, or `git checkout -- <file>`.
- No merge, no push, no flash.
- End every commit message with the `Co-Authored-By:` line for the model doing the work.

**Code conventions**
- Logs are English and use `ESP_LOGI`/`ESP_LOGW`, one line per state change only. Nothing may log on every tick.
- User-facing text is Thai.
- Time is `uint32_t` uptime ms, and elapsed time is computed with unsigned subtraction.
- Web POST handlers use `api_begin_json_post`. Errors go through `send_api_error(req, code, message, status)`.
- `main/static_compressed/*` is regenerated by the build (`scripts/optimize_assets.py`). Commit it with the task that changed `main/static/*`.
- UI uses `textContent`, never `innerHTML`, for any text that comes from the board.
- Dry-run protection, pump control and cooling behaviour must not change, except where Task 6 says so.

## Review Focus

1. **Rules saved by the current firmware (blob v1) must load unchanged after this OTA.** If they don't, the user's tuned rules silently fall back to disabled presets. Pinned in Task 2 by a hand-built v1 blob test.
2. **`uplink_set_sink(NULL)` while a send is in flight.** Once it returns, nothing may call into the old `ctx`. Pinned in Task 3 by static checks: `set_sink` takes `send_lock`, and every `s.sink.` use sits under it.
3. **Holding events for the clock must not lose them.** With 24 or more events pending, events are sent without `ts` instead of waiting until the ring overwrites them. Pinned in Task 3 by a pure test.
4. **The critical overlay.** After "ปิดไว้ก่อน" it must stay closed on every later poll, and it must open again for a newer critical event. Pinned in Task 8 by static checks on the dismissed-seq storage, and in the Task 9 bench steps.
5. **LED priority.** Staging, recovery AP, button hold and factory reset still override every alarm colour. Critical beats warning, and warning beats info. Pinned in Task 1 (pure level test) and Task 4 (static order check).

### Task 2: Rule blob v2 with record size, v1 migration (review 2)

**Files:**
- Modify: `firmware/components/alarm_rules/include/alarm_rules.h`, `firmware/components/alarm_rules/alarm_blob.c`
- Modify: `firmware/components/nvs_store/nvs_store.c` (only the alarm-rule blob load size limit, near line 1877)
- Test: the self-test file that already tests `alarm_blob_encode`/`decode` (grep for it)
- Modify: `firmware/scripts/verify_pre_mqtt.py`

**Interfaces:**
- Produces:
  - `#define ALARM_BLOB_VERSION 2`
  - `#define ALARM_BLOB_V1 1`
  - `#define ALARM_BLOB_HEADER_BYTES 6`
  - `#define ALARM_BLOB_MAX_BYTES (ALARM_BLOB_HEADER_BYTES + ALARM_MAX_RULES * sizeof(alarm_rule_t))`, the write size
  - `#define ALARM_BLOB_READ_MAX_BYTES (ALARM_BLOB_HEADER_BYTES + ALARM_MAX_RULES * (sizeof(alarm_rule_t) + 64))`, the read limit, so a future larger record still loads
  - The signatures of `alarm_blob_encode` and `alarm_blob_decode` are unchanged.
- Layout v2: `[2][count][next_id lo][next_id hi][rec_size lo][rec_size hi][count × rec_size bytes]`.
- Layout v1, read only: `[1][count][next_id lo][next_id hi][count × sizeof(alarm_rule_t)]`.

- [ ] **Step 1: Write the failing tests:**
  - **v2 round-trip:** encode the presets, check `buf[0] == 2` and `rec_size == sizeof(alarm_rule_t)`, then decode to an equal set with `dropped == 0`.
  - **Hand-built v1 blob:** header `1, count, next_id` plus raw `memcpy` of 3 valid rules. It decodes to the same 3 rules and the same `next_id`.
  - **Larger v2 record** (`rec_size = sizeof + 8`, extra bytes 0xAA): it decodes, and the rules equal the originals.
  - **Smaller v2 record** (`rec_size = sizeof - 4`): decode returns without reading past `len`. The result is either false or a set whose rules all pass `alarm_rule_validate`.
  - **Length mismatch:** `len != 6 + count*rec_size` → false. `rec_size == 0` → false.
  - **Unknown version 3** → false.

- [ ] **Step 2: Run the self-test.** Expected: v2 checks FAIL.

- [ ] **Step 3: Implement.**
  - `encode` writes v2.
  - `decode` accepts v1 with the old exact-length rule, and v2 with any `rec_size` in 1..1024.
  - Copy `min(rec_size, sizeof)` bytes into a zeroed `alarm_rule_t`, then validate exactly as today.
  - `nvs_store` checks the loaded length against `ALARM_BLOB_READ_MAX_BYTES` and allocates that size.
  - Put a comment on `alarm_rule_t`: fields are append-only, and 0 must mean the default.

- [ ] **Step 4: verify_pre_mqtt "Task 2" checks:**
  - `ALARM_BLOB_VERSION 2`
  - decode references `ALARM_BLOB_V1`
  - `nvs_store.c` uses `ALARM_BLOB_READ_MAX_BYTES`

- [ ] **Step 5: Run all gates.**

- [ ] **Step 6: Commit** `feat(alarms): versioned rule blob with record size; read v1 blobs`
