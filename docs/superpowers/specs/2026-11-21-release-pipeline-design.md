# ออกแบบ: ระบบ release, คีย์ OTA และแพ็กเกจติดตั้ง

วันที่: 2026-11-21 · สถานะ: **ร่าง รอผู้ใช้อนุมัติ** · ขนาดงาน: โปรเจกต์ (หลายส่วน แต่เป็นเรื่องเดียวกัน)

## 1. เจตนาและเหตุผล

ผู้ใช้ต้องดูแล firmware นี้ **2-3 ปีขึ้นไป** และอาจส่งให้นักพัฒนาคนอื่นรับช่วง จึงต้องการให้
- build รุ่น release ทำซ้ำได้ผลเหมือนเดิมไม่ว่าใครหรือเครื่องไหนเป็นคนสั่ง
- คีย์ OTA ไม่หลุดและไม่หายเงียบๆ ระหว่างเปลี่ยนเครื่องหรือเปลี่ยนคน
- ติดตั้งบอร์ดใหม่ง่ายเหมือนโปรเจกต์เก่า (`fish-pump-RelayTimerControl`) และยังรู้รหัส Wi-Fi AP ของบอร์ดได้
- อัปเดตบอร์ดที่ติดตั้งแล้ว (ทางเว็บและทาง ThingsBoard) ได้ต่อเนื่องโดยไม่ต้องต่อสาย

## 2. สภาพปัจจุบัน (ตรวจแล้ว 2026-11-21)

- web OTA (`POST /api/ota`, `firmware/main/web_server.c`) รับไฟล์ที่เข้ารหัสแล้ว: IV 16 ไบต์ + AES-256-CTR ใช้คีย์ `APP_CONFIG_OTA_ENCRYPTION_KEY`
- คีย์มาจาก `secrets.h` (gitignore ไม่ครอบคลุม และไม่มีไฟล์นี้ใน repo) ถ้าไม่มีไฟล์ `app_config.h` จะ build ผ่านเงียบๆ ด้วยคีย์ศูนย์ → **บอร์ดบนโต๊ะทุกตัวใช้คีย์ศูนย์**
- OTA ผ่าน ThingsBoard (`tb_ota.c`) ไม่ถอดรหัส รับไฟล์ธรรมดา ขณะที่ web OTA รับไฟล์เข้ารหัส
- web OTA จำกัดไฟล์ไว้ 1,966,080 ไบต์ แต่ image ปัจจุบัน ~2.06 MB (partition ota_0/ota_1 ขนาด 0x380000) → อัปโหลด 0.4.0 ทางเว็บได้ 413
- ไม่มี CI, ไม่มีบันทึกเวอร์ชัน ESP-IDF (เครื่องผู้ใช้ใช้ v6.0.1), `firmware/dependencies.lock` ถูก gitignore, `led_strip` และ `max31865` ระบุเวอร์ชัน `*`
- ไม่มีสคริปต์เข้ารหัส/แพ็กเกจ/แฟลชใน repo นี้ แต่โปรเจกต์เก่ามีครบ (`generate_secrets.ps1`, `encrypt_ota.py`, `package.ps1`, `FLASH.bat`, `SHOW_PASSWORD.bat`, `ERASE_FLASH.bat`, `show_ap_password.ps1`, `esptool.exe`, README ลูกค้า) และ **เข้ากันได้กับ firmware ปัจจุบัน**: CTR + IV 16 ไบต์ตรงกัน, สูตรรหัส AP (MAC ไบต์ 2-5 XOR 0x5A, 8 ตัวฐานสิบหก) ตรงกับ `wifi_manager_build_ap_password`

## 3. เป้าหมาย / ไม่ใช่เป้าหมาย / สิ่งที่ถือว่าล้มเหลว

เป้าหมาย
1. ไฟล์ release ทุกตัวมาจาก CI ของ repo นี้ (GitHub Actions) เท่านั้น
2. build รุ่น release ล้มเหลวเมื่อไม่มีคีย์หรือคีย์เป็นศูนย์
3. ผู้ใช้และบอร์ดเทียบ "ลายนิ้วมือคีย์" ได้ว่าตรงกัน
4. ชุดติดตั้ง (factory `.bin` รวม + สคริปต์แฟลช + อ่านรหัส AP) ใช้ได้เหมือนเดิม
5. เอกสารส่งมอบให้คนใหม่ทำต่อได้โดยไม่ต้องถามผู้ใช้
6. แก้ขีดจำกัดขนาด web OTA

ไม่ใช่เป้าหมายรอบนี้
- secure boot / flash encryption / ลายเซ็นไฟล์ OTA (บันทึกเป็นงานภายหลัง ถ้าขายหลายลูกค้า)
- คีย์แยกรายบอร์ด
- การทำ TLS ของ ThingsBoard (อยู่ในแผน VPS deploy แยก)
- ตัวฟรอนต์เอนด์

ล้มเหลวแม้ build ผ่าน: บอร์ดที่อัปเดตแล้วเปลี่ยนไปใช้คีย์ศูนย์โดยไม่มีใครรู้ หรือคีย์หายจนบอร์ดต้องใช้สายแฟลช

## 4. ข้อจำกัด

- คีย์ไม่เข้า git และไม่ควรอยู่ในโฟลเดอร์ที่ซิงก์ OneDrive ต่อไป
- ห้ามพิมพ์ตัวคีย์หรือรหัส AP ที่คำนวณได้ในเอกสาร/แชต/log ของ CI
- ผู้ใช้ทำขั้นตอนที่ต้องล็อกอิน ตั้งค่า secret และแฟลชบอร์ดเอง
- ต้องใช้ได้บน Windows (สคริปต์ PowerShell) และ CI (Linux)

## 6. การออกแบบ

### 6.1 Build ทำซ้ำได้
- ระบุเวอร์ชัน ESP-IDF ใน repo (ไฟล์เดียว เช่น `firmware/IDF_VERSION`) ค่าเริ่มต้น v6.0.1 ตามเครื่องผู้ใช้ และให้ CI อ่านจากไฟล์นี้
- commit `firmware/dependencies.lock` (เอาออกจาก `.gitignore`) และเปลี่ยน `*` ใน `idf_component.yml` เป็นช่วงเวอร์ชันที่แน่นอน
- sdkconfig มาจาก `sdkconfig.defaults` เท่านั้น (`sdkconfig` ที่สร้างเองไม่ใช่แหล่งความจริง)

### 6.2 คีย์และลายนิ้วมือ
- `firmware/scripts/generate_secrets.ps1` (port จากโปรเจกต์เก่า) สร้างคีย์สุ่ม 32 ไบต์ลง `secrets.h` ปฏิเสธการเขียนทับ และพิมพ์เฉพาะลายนิ้วมือ ไม่พิมพ์ตัวคีย์ (คีย์ไปเก็บเองจากไฟล์/ที่เก็บคีย์)
- เพิ่ม `firmware/components/app_config/secrets.h` และ `firmware/**/secrets.h` ใน `.gitignore`
- **กติกาคีย์ release:** ตอน build ที่ตั้งโหมด release (`FISHPUMP_RELEASE=1` หรือ CMake option) ถ้าไม่มี `secrets.h` หรือคีย์เป็นศูนย์/ค่าตัวอย่าง → CMake `FATAL_ERROR` build dev ยังใช้คีย์ศูนย์ได้ และติดป้ายใน log/attribute ว่า `dev`
- ลายนิ้วมือ = SHA-256 ของคีย์ ตัด 8 ตัวอักษรแรก คำนวณทั้งตอน build (พิมพ์ใน log, ใส่ในชื่อไฟล์ release) และบนบอร์ด (log ตอนบูต + attribute ของ ThingsBoard + ฟิลด์ใน `/api/status`) ต้องไม่เปิดเผยตัวคีย์
- ผู้ใช้เก็บคีย์ไว้ใน GitHub secret `OTA_ENCRYPTION_KEY` **และ** ที่สำรองนอก GitHub (โปรแกรมจัดการรหัสผ่านหรือที่เก็บออฟไลน์) สองที่เสมอ

### 6.3 CI (GitHub Actions)
- workflow `ci.yml`: ทุก PR และ push ไป main รัน `run_selftest.ps1` ส่วนที่รันบน Linux ได้ (ถ้ารันไม่ได้ ให้ port เป็น script ที่เทียบเท่า), `verify_*.py`, และ build dev ด้วย image `espressif/idf` ที่ตรึงเวอร์ชัน
- workflow `release.yml`: ทำงานเมื่อ push tag `v*.*.*` ตรวจว่า tag ตรงกับ `firmware/version.txt` → build โหมด release ด้วยคีย์จาก secret → สร้างไฟล์แนบ → สร้าง GitHub Release
- ไฟล์ที่แนบ: `fishpump-<ver>-<keyfp>.ota.bin` (เข้ารหัสสำหรับ web OTA), `fishpump-<ver>.bin` (ธรรมดา สำหรับ ThingsBoard OTA), `fishpump-<ver>-factory.bin` (bootloader+partition+otadata+app รวมที่ offset 0x0), `flash-package.zip` (ชุดติดตั้ง), `SHA256SUMS`
- ห้ามพิมพ์คีย์ใน log (ใช้ secret masking และไม่ `echo` ตัวแปร)
- ต้องยืนยันตอนลงมือว่ามี image `espressif/idf:<ver>` ของเวอร์ชันที่ใช้จริง ถ้าไม่มีให้ติดตั้ง ESP-IDF ใน workflow

### 6.4 สคริปต์และแพ็กเกจติดตั้ง (port จากโปรเจกต์เก่า ปรับให้เข้ากับ repo นี้)
- `encrypt_ota.py` (ย้ายมาตรงๆ รับคีย์จากตัวแปรสภาพแวดล้อมหรือไฟล์ ไม่รับเป็นอาร์กิวเมนต์บรรทัดคำสั่ง เพื่อไม่ให้คีย์ปรากฏใน process list/log) พร้อมเทสต์ round-trip ที่เทียบกับ `esp_aes_crypt_ctr` ผ่านเวกเตอร์ทดสอบ
- `package.ps1` (ปรับให้ใช้ build เดียว esp32s3, ชื่อไฟล์ `fishpump.bin`, ที่อยู่ `firmware/build/`) และสร้าง factory `.bin` ด้วย `esptool merge-bin`
- `FLASH.bat`, `ERASE_FLASH.bat`, `SHOW_PASSWORD.bat` + `flash_and_show.ps1`, `erase_flash.ps1`, `show_ap_password.ps1`, `esptool.exe` (ดาวน์โหลดตอนแพ็กเกจ ไม่ commit ไฟล์ไบนารี), README ลูกค้า ไทย/อังกฤษ
- `show_ap_password.ps1` อ่าน MAC จากบอร์ดแล้วคำนวณรหัส AP ด้วยสูตรเดียวกับ firmware (บันทึกวิธีคำนวณ ไม่เขียนค่าจริงของบอร์ดใดลงเอกสาร) และมีเทสต์เวกเตอร์เทียบสูตรใน `wifi_manager.c`
- ไม่ copy ของที่ไม่เกี่ยว: build รุ่น esp32 เดิม, `flash_com5.ps1`, ไฟล์ simulator/mock ของโปรเจกต์เก่า (ไว้พิจารณาแยก)

### 6.5 แก้ web OTA
- ขีดจำกัดขนาด `POST /api/ota` ให้ตามขนาด partition (0x380000) + 16 ไบต์ IV ไม่ใช่ค่าคงที่เล็กกว่า image จริง เพิ่มเทสต์ขอบเขต (ไฟล์พอดี/เกินเล็กน้อย)
- แยกระบุในเอกสารว่า web OTA รับไฟล์เข้ารหัส และ ThingsBoard OTA รับไฟล์ธรรมดา (ตัดสินใจแล้วว่ายังปล่อยแบบนี้ รอบนี้ ความลับของ ThingsBoard OTA แก้ด้วย TLS ตอนขึ้น VPS)

### 6.6 ย้ายบอร์ดจากคีย์ศูนย์เป็นคีย์จริง (ครั้งเดียว)
บอร์ดบนโต๊ะใช้คีย์ศูนย์ ขั้นตอน: build release ด้วยคีย์ใหม่ → เข้ารหัสไฟล์นั้น **ด้วยคีย์ศูนย์** → อัปโหลดทาง web OTA (หลังแก้ 6.5) หรืออัปโหลดไฟล์ธรรมดาผ่าน ThingsBoard → บอร์ดบูตด้วยคีย์ใหม่ และ attribute ลายนิ้วมือต้องตรงกับที่ CI พิมพ์ ถ้าเหตุขัดข้อง ต่อสายแฟลช factory `.bin` ได้เสมอ
การเปลี่ยนคีย์ในอนาคตใช้ขั้นตอนเดียวกัน: เข้ารหัสไฟล์ที่มีคีย์ใหม่ด้วย **คีย์เก่า** อัปเดตทีละบอร์ด แล้วเลิกใช้คีย์เก่า

### 6.7 เอกสารส่งมอบ (`docs/release/`)
- `README.md`: ภาพรวมและแผนผังว่าอะไรอยู่ที่ไหน
- `keys.md`: สร้าง สำรอง กู้ เปลี่ยนคีย์ และตรวจลายนิ้วมือ
- `release.md`: ขั้นตอนออก release ทีละข้อ (แก้ `version.txt` → PR → merge → tag)
- `install.md`: ติดตั้งบอร์ดใหม่ อ่านรหัส AP อัปเดตผ่านเว็บ/ThingsBoard
- `handover.md`: รายการสิ่งที่ผู้รับช่วงต้องได้ (สิทธิ์ GitHub, secret, ที่สำรองคีย์, เวอร์ชัน ESP-IDF, บัญชี ThingsBoard) และสิ่งที่ยังค้าง
